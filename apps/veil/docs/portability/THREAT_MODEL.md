# Portability threat review — beta, not independently audited

Trust: endpoints and their unlocked memory, libsignal, JOSE/JCA/OpenSSL, Android OS/Keystore, trusted initial identity comparison, and user custody of recovery key. Providers are untrusted for message confidentiality and identity signatures; cooperative providers enforce availability/quotas/deletion. Network attackers are covered by HTTPS and signatures. No phone/email/contact upload, analytics or push preview added.

| Threat | Prevention / friction | Remaining possibility | Verification |
|---|---|---|---|
| Lost phone | Android Keystore encrypts atomic no-backup vault, OS unlocked-device restriction, app biometric/device credential lock; export restores control elsewhere | Unlocked/rooted attacker can extract live exportable controller material; lost device may keep using old state until a provider/contact learns the newer one | Existing unlock/protection instrumentation; JWE fresh restore and device-key rotation tests |
| Stolen encrypted backup | Standard JWE dir/A256GCM with random 256-bit separate recovery key | Both ciphertext and secret confer control; weak substituted passwords are not accepted; no company reset | Wrong-secret and real restore tests; bounded import |
| Malicious provider / backend compromise | User-signed state/routes/grants/Signal bundles; messages encrypted with existing libsignal; no issuer/master secret | Denial, delayed delivery, traffic analysis, replay of old state to parties that never saw newer state; operator can retain ciphertext/metadata | Independent verifier; forged controller/claims, stale revision and A-offline tests; wire/private-key checks |
| Key substitution / hostile directory | Pin controller from trusted card; verify all channel bindings/grants against that key; manual full safety number | First directory lookup is TOFU; a fake name with a different valid key can fool someone who never verifies it | Wrong-controller/new-route tests; safety-number regressions |
| Nonce / request replay | Device-signed exact request and state hashes, audience/time binding, one-use nonce; atomic provider lock | Network retry must use fresh nonce; captured valid proof can race one use but cannot change its operation; clock skew can cause denial | Nonce replay, hash mutation, wrong audience, expiry tests |
| Device key theft | New controller-signed state delegates fresh key; known previous state rejected | No universal instantaneous revocation, unrelated/offline providers may not know; controller compromise is worse | Rotation + stale-authority tests; explicit UI limit |
| Controller/recovery compromise | Separate operational keys reduce the need to use controller for routine requests | No safe in-place root rotation for a fingerprint. Attacker with controller can impersonate it; create new facet/identity and independently re-enroll contacts | Core rejects unsupported root rotation; documentation, no fictional recovery chain |
| Spam / Sybil | One introduction/relationship, explicit signed approval, limits, bounds, blocked/revoked terminal grants, per-contact channels | Creating many keys is cheap; public internet needs operator-level IP/connection abuse controls; no false “anonymous means abuse-proof” claim | Rate/duplicate intro, unsigned grant and revocation tests |
| Mistaken policy interpretation | Exact supported grammar or manual form, canonical review and explicit confirmation; unsupported media/phrasing fails | Users may choose wrong time zone or misunderstanding; policy is not enforceable against a modified recipient after plaintext arrives | Global grammar negative tests, editor regression, DST boundaries |
| Old backup / rollback | Persist known highest state/grant revisions; latest backup includes terminal grants; no automatic publication/import | Old backup lacks later revocations/received state; restoring it on a new provider may revive old permissions. User must review restored grants. No transparency/witness consensus yet | Stale known-state tests, migration docs; unseen rollback is an explicit limitation |
| Provider downtime / shutdown | Offline key control, independent verifier, independent new service, signed route card through external channel | Recipient needs the new card, compatible service and internet; old queues/history/handles do not magically return | A subprocess stopped, DB removed, refused port, transport refuses A during fresh restore/new Signal exchange |
| Cross-purpose / contact graph linkage | Independent random purpose keys; no public wallet root; listing contains only chosen purpose; no contact list in public cards | Same provider sees IP, requests, purpose IDs, relationships, grants, policy and timing; public names/photos elsewhere can correlate; encrypted backup groups own relationships | Private discovery/independent ID tests, protocol field audit |
| Local files, logs, backups | Atomic AES-GCM Keystore vault in noBackupFilesDir; SAF exports JWE only; allowBackup false inherited; generic errors, no plaintext notifications/logs | Root/memory compromise, flash recovery of historical encrypted blocks, third-party document provider retention, strings cannot be deterministically zeroed on JVM | Existing app backup/storage configuration, wire/DB tests, manual file-picker/physical extraction still required |
| Screenshots/recording/sharing/recents | Existing FLAG_SECURE, conceal-on-background, overlay restriction, recents opt-out; existing media press/hold + watermark preserved | OEM differences, privileged/root capture, accessibility services, external camera. Portable text isn't a DRM guarantee | Existing emulator capture/hold/background regressions; OEM screen-share and external camera remain physical tests |
| Revocation / deletion | Current provider rejects future sends, removes queued ciphertext; local confirmed revocation fails closed and retries publication | Other/offline providers may have stale state; recipient's already received content and stolen backups cannot be remotely erased | Queue deletion, terminal retry, expiry and after-migration revocation tests |

Server visibility is explicit: IP/transport timing at hosting layers; per-purpose public keys, device public key, signed policy/route, relationship endpoints/IDs, grants/decisions/expiry, Signal public prekeys, ciphertext sizes/timing. No message plaintext, Signal private keys, private controller/wallet keys, recovery secret, phone or email is transmitted by the app. Provider implementations contain no calls to another identity authority.

Physical capture tests and independent security review remain required before production claims. Separate CI processes/DBs prove technical independence, not independence of human operators or infrastructure providers.
