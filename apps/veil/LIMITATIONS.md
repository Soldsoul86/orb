# Limits of this portability beta

- This is an additive Android beta. Existing personal chat/Signal/media/protection and the earlier v2 purpose vault remain separate. They are **not retroactively converted** into portable identities. A new portable wallet is created under My identity; no existing chat is reset.
- The demonstration uses isolated provider processes, separate SQLite databases/origins and independently usable Python verification. Those processes are administered by the same test operator on one CI host. No claim of independent organizations or deployed production federation is made.
- The working Render relay has not been replaced, stopped or silently upgraded to pi/1. Public pi/1 hosting is not configured. The APK needs compatible HTTPS provider origins for portable messaging; offline identity/recovery is available without them.
- JWK thumbprint is an immutable key identifier, not a legal identity, DID method, human-readable handle or revocable global person record. No native controller-key rotation. Controller compromise means new identity and trusted re-enrollment; device keys can rotate under an unchanged safe controller.
- Recovery requires both encrypted package and separate random recovery key. No company master key, OTP or password reset. Export excludes messages, live Signal ratchets, outbox and operational device keys. Keep a fresh backup after policy/grant updates.
- Migration restores owner-controlled approved/unexpired grants and keeps those purpose controller IDs. Outgoing-only peer session recovery needs owner reissue and is not automated. Pending requests, old queues/history and provider directory handles do not migrate. At most four first-contact/restore slots per purpose per epoch; replenishment UI is not implemented. More than four approved relationships cannot all migrate in this beta.
- Contacts receive a new signed card through another channel, then explicitly accept the same pinned controller and a fresh Signal session. Safety numbers change. There is no automatic worldwide route lookup, no company registry substitute and no claim of seamless discovery after shutdown.
- Known revisions reject rollback; an old backup/new verifier can miss later revocations. No global witness/transparency/freshness consensus. On restore, the owner reviews grants before publication; do not treat this as robust compromise recovery.
- Portable purposes support text only, one introduction then explicit approval, same-day schedules, IANA zones/DST, reject or bounded queue, grant/purpose expiry, pause/revoke and device rotation. Documents/media, overnight schedules, holidays, automatic approval, multi-device simultaneous use and fine-grained delegate credentials are absent. Original personal-chat photo/video remains available.
- Messages expire after seven days, including queue time. Foreground unlocked manual refresh is used for portable delivery; no background push or previews. Clients and providers cannot retract plaintext already delivered to a modified/compromised recipient.
- Separate purpose keys reduce public linkage, not metadata correlation. A provider can see its purpose/relationship routing and policies. Reusing a purpose links its contacts. Backups reveal the user's authorized relationship graph to whoever has both backup and key.
- Preview uses a preserved development signing certificate, not a production release/distribution process. Original v0.1 signing key is unavailable, so the preview remains a separate package rather than destroying an installed personal-chat identity.
- Not independently security-audited. Rooted/unlocked devices, accessibility/OEM differences, external-camera capture, full physical backup/recovery UX and internet operations require additional testing. FLAG_SECURE is best-effort supported OS protection, not a guarantee against every capture path.
