# Development-only contracts

- `parseAddress(url, trustedOrigin)` accepts canonical HTTPS `/g/<43-character canonical RFC7638 public thumbprint>` with an optional canonical 32-byte base64url invitation reference in the fragment. Returns public controller ID, exact origin, reference and reusable/unlisted type. Rejects the old unpinned `/i#token`, userinfo, query, redirects, dot segments, percent encodings, Unicode path aliases, fragments of other sizes, implicit default-port normalization and a different origin. The trusted origin must come from reviewed configuration, not arbitrary resolver output. Domain ownership is an operational prerequisite, not proven by parsing.
- `verifyStatement(compactJws, expectedId, type)` verifies existing pi/1 ES256/JWS public statements using Web Crypto, exact JOSE headers, canonical base64url, duplicate-key rejection and independently pinned RFC7638 ID. It authenticates signed bytes; it does NOT grant access, evaluate expiration/office hours, install Signal keys or decrypt messages.
- `verifyState(token, address, minimumRevision)` additionally checks identity/state fields, device key validity, expected route, known revision floor and display metadata. It refuses reusable resolution of UNLISTED metadata. It does not establish global freshness, real-world name ownership, full authorization policy validity or migration discovery.
- `transition` and `installVisible` are presentation helpers only. `authenticated:true` in unit fixtures is not cryptographic evidence and must never become an authorization API. The actual app never feeds network events to these helpers in this disabled build.
- `sendGuestMessage()` always rejects with `BROWSER_CRYPTO_UNAVAILABLE`. No encryption interface pretending to work, no fallback endpoint.
- Development server: exact GET/HEAD assets only. `/guest-capabilities` reports false. All mutations, including direct POSTs, return 503 and close without reading the body. No provider access. No CORS allowance. Host must match loopback listener; no public bind option.

User-facing state copy lives in `src/state.mjs`. Optional install wording intentionally avoids promising background notifications or session continuity that current Veil does not implement. The Get Veil link is not wired until an authenticated, decrypted reply exists in a functioning channel. The fixture renderer displays state copy only; Send remains disabled in every state.

Future integration contract: use existing signed device proofs and scoped owner grants; don't convert the public URL into guest authentication. Name belongs inside authenticated encrypted content, not plaintext routing fields. Extend versioned envelope semantics explicitly if adding a name. Existing v9 Android QR creation and `/i` download page are unchanged.
