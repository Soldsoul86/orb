# Scan → install → continue

The existing contact QR encodes the same HTTPS `/i#<opaque invitation>` as Share invitation. A phone camera can open this page before Veil is installed. It now offers a direct public APK download, without GitHub sign-in, a ZIP, WhatsApp, NFC or an in-app scanner. The download opens separately; the invitation stays in the original tab. After installation, return there and tap **Continue in Veil**, then request contact. The owner still approves.

This does **not** meet fully automatic post-install continuation. The current APK sideload has no deferred-invitation mechanism; installer Open starts normal app navigation without the browser fragment. We do not fingerprint devices, automatically read the clipboard, append invitations to public download URLs, or claim installation detection. [Play Install Referrer](https://developer.android.com/google/play/installreferrer) is a possible future distribution integration, requiring a Play Console account and a separate privacy review; it is not implemented here and would not itself silently launch an app after installation.

The immutable v7 APK comes from successful run 39200435127. Release publication checks SHA-256 `143f7ee0371c9b9d1678f28cfcc6bcf10859bf4a8aed1c8ad54caac536029b07`; existing releases are verified, never overwritten. App code, signer, stored data, encryption, invitation approval and expiry are unchanged. Browser downloads may require an Android confirmation/allow-install permission.

`browser_check.py` runs Chromium against the actual relay handler with its CSP and referrer headers. It exercises the download control with a deliberately synthetic download response, confirms the original invitation survives download/reload, rejects invalid fragments and checks no token is sent in HTTP URLs/referrers. With `--origin https://veil-relay-soldsoul86.onrender.com`, it also downloads the real public APK without authentication and compares its checksum. The synthetic download response is never installed or published.

Physical camera scanning, the Android installer, browser-to-app resolution and OEM behavior still require two-phone testing. Keep the original browser tab open; the fallback is to scan the same QR again if that tab is lost. Installed phones may open Veil directly through Android App Links. Deleting a tab/history loses the browser invitation; no provider-based device matching exists.

Manual test: on a phone without Veil, scan a real QR using the system camera; download/install; return to the original tab; tap Continue in Veil; unlock; confirm the correct invitation; request; approve on the owner phone; exchange text. Also test an already installed phone and a cancelled invitation. Report automatic post-install continuation as NOT IMPLEMENTED, not PASS.
